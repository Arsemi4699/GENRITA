# GRPipeline: Hybrid Intelligence System for Text Analysis

**GRPipeline** is an advanced, driver-based Python system for deep text analysis. It provides a complete, asynchronous API (built with FastAPI and Redis) for running a sophisticated analysis pipeline on unstructured text documents.

The system is composed of two primary modules:

1.  **GENRITA**: A multi-task semantic classifier for identifying the **Sense** (thematic mood/genre) and **Age** (temporal period) of a text passage.
2.  **ROAST**: An advanced instance extractor for identifying and unifying specific entities (e.g., "Geralt", "Geralt of Rivia") based on abstract concepts (e.g., "witcher").

The core of this project is its **driver-based architecture**, which allows the backend for each module to be hot-swapped between a specialized, fine-tuned **Neural Network (NN)** and a general-purpose **Large Language Model (LLM)**, enabling a clear comparison of performance, speed, and accuracy for each task.

-----

## Core Features

  * **Asynchronous API**: Built with FastAPI and a Redis job queue (`api.py`) to handle long-running analysis tasks without blocking.
  * **Dual-Module Analysis**: Performs both high-level semantic classification (GENRITA) and low-level entity extraction (ROAST) in a single pipeline.
  * **Driver-Based Architecture**: Easily switch between a fine-tuned `NNDriver` and a generative `LLMDriver` (via Ollama) for both classification and extraction, based on your needs for speed vs. accuracy.
  * **Multi-Task Classification**: The **GENRITA** module's NN-Driver (`model.py`) uses a `RoBERTaMultiTaskClassifier` to predict `Sense` (11 classes) and `Age` (3 classes) simultaneously.
  * **Advanced Instance Extraction**: The **ROAST** module's LLM-Driver uses few-shot prompting, self-correction, and fuzzy matching to extract specific instances of abstract concepts with high precision.
  * **Dynamic Entity Unification**: Includes a sophisticated entity unifier (`_unify_entities`) that normalizes extracted entities across an entire document (e.g., "Geralt" and "the Geralt of revia" are both unified to "the Geralt of revia").
  * **Synthetic Data Generation**: Comes with a powerful data generator (`data/generator.py`) that uses an LLM to create a high-quality, diverse training dataset for the classifier.
  * **Comprehensive Benchmarking**: Includes full scripts and results (`genrita_bench/`, `roast_bench/`) for evaluating the performance of all available drivers.

-----

## System Architecture

The GRPipeline operates as a job-based system. A user submits a text file and a configuration JSON, and the system processes the document in the background.

#### High-Level System Flow

```
   User Request
(File + Config JSON)
       |
       v
[ FastAPI API (/process) ]
       |
       v
[ Redis Job Queue ] <--- [ Background Worker (pulls job) ]
       |
(Returns Job ID)         [ GRPipeline Orchestrator (GRP.py) ]
       |                 |
       |<----------------+ (Loop per Paragraph)
       |                 |
       |                 +----[ 1. Text Chunker ]
       |                 |
       |                 +----[ 2. GENRITA Driver (NN or LLM) ] ---> (Sense/Age Prediction)
       |                 |
       |                 +----[ 3. ROAST Driver (NN or LLM) ] ---> (Raw Entities)
       |                 |
       |                 +----[ 4. Entity Unifier ] ---> (Unified Entities)
       |                 |
       |                 +----[ 5. Result Combiner ]
       |                 |
       |                 +----[ 6. Save to JSON File ]
       |                 |
(User polls /results)    +----[ 7. Update Job Status in Redis ]
       |
(User downloads /download)
```

#### Key Modules Explained

1.  **GENRITA (Semantic Classifier)**

      * **NN-Driver**: Uses the `RoBERTaMultiTaskClassifier` (`model.py`), a PyTorch Lightning model fine-tuned on the synthetic dataset generated by `data/generator.py`. It provides fast and highly accurate predictions for the specific `Sense` and `Age` classes.
      * **LLM-Driver**: Uses few-shot prompting (`GENRITA.py`) to ask an Ollama-served LLM to classify the text and return a JSON object of probabilities. This is slower but requires no training.

2.  **ROAST (Instance Extractor)**

      * **NN-Driver**: Uses Haystack and an Extractive QA model (`QA_RoBERTA_SQUADv2`). It reframes the task by generating questions (e.g., "Which dragons are in the text?") and extracting the answers.
      * **LLM-Driver**: Uses a generative LLM with a detailed few-shot prompt to generate a Python list of instances directly. This driver includes two key innovations:
          * **Self-Correction**: If the LLM's output is not a valid list, the driver automatically sends the bad output back to the LLM and asks it to fix it.
          * **Fuzzy Position Matching**: It uses `thefuzz` to find the exact location of the (sometimes slightly modified) generated text within the original paragraph.

3.  **Entity Unifier (`_unify_entities`)**
    This crucial post-processing step ensures that all references to the same entity are standardized.

      * It maintains a **canonical bank** of entities for the entire document (e.g., `{"witcher": {"Geralt of Rivia", "Vesemir"}}`).
      * For each new entity, it calculates a combined similarity score (using `fuzz.ratio` and `fuzz.partial_ratio` after removing stopwords).
      * If a match above a threshold (e.g., 70) is found, it uses the canonical version.
      * It intelligently **updates the canonical bank** if a more complete version of an entity is found (e.g., it replaces "Geralt" with "Geralt of Rivia" in the bank).

## Benchmark & Performance

The repository includes a full suite of benchmarks comparing the NN and LLM drivers for each module.

### **GENRITA (Classification) Results**

For semantic classification, the fine-tuned **RoBERTa (NN-Driver)** is the clear winner, significantly outperforming all tested LLM drivers.

| Driver / Model | Sense Accuracy | Age Accuracy |
| :--- | :---: | :---: |
| **NN-Driver (RoBERTa)** | **85.0%** | **80.0%** |
| LLM-Driver (gemma3) | 63.0% | 52.0% |
| LLM-Driver (phi4-mini) | 62.0% | 54.0% |
| LLM-Driver (llama3.2) | 42.0% | 44.0% |

*Data from `genrita_bench/`*

### **ROAST (Extraction) Results**

For instance extraction, the **LLM-Drivers** are vastly superior, demonstrating a powerful ability to understand abstract concepts and generate accurate results.

| Driver / Model | F1-Score | Total Time (sec) |
| :--- | :---: | :---: |
| **LLM-Driver (phi4-mini)** | **98.3%** | 41 |
| LLM-Driver (gemma3:12b) | 98.2% | 787 |
| LLM-Driver (llama3.2) | 97.8% | 30 |
| **NN-Driver (QA\_RoBERTA)** | **66.4%** | **2** |

*Data from `roast_bench/result_roast.txt`*

### **Conclusion**

  * **For GENRITA (Classification):** Use the **NN-Driver** for fast and accurate results.
  * **For ROAST (Extraction):** Use the **LLM-Driver** (e.g., `phi4-mini`) for exceptional accuracy, but be mindful of the longer processing time.

## Installation

1.  **Clone the repository:**

    ```bash
    git clone https://github.com/Arsemi4699/GENRITA.git
    cd GENRITA
    ```

2.  **Install Python dependencies:**

    ```bash
    pip install -r requirements.txt
    ```

3.  **Set up dependencies:**

      * **Models:** This system requires local models. Download the fine-tuned classifier checkpoint (e.g., `best-model.ckpt`) into a `/checkpoints` directory. Download the Extractive QA models (e.g., `QA_RoBERTA_SQUADv2`) into their respective directories. The `predownload.py` script can help with this.
      * **Ollama:** For LLM-Drivers, you must have an **Ollama** server running and have pulled the required models (e.g., `ollama pull phi4-mini`).
      * **Redis:** You must have a **Redis** server running on `localhost:6379`.

## How to Use the API

The API provides three main endpoints for an asynchronous workflow.

### 1\. Submit a Processing Job

Send a `POST` request to this endpoint to start a new analysis job.

  * **Endpoint:** `POST /process`
  * **Request Type:** `multipart/form-data`
  * **Form Fields:**
      * `file`: The `.txt` file to be analyzed.
      * `config_json`: A **string** containing the JSON configuration.

**Example `config_json`:**

```json
{
  "title": "My Document Analysis",
  "classifier_driver": "nn",
  "extractor_driver": "llm",
  "confidence_threshold": 0.85,
  "allowed_senses": [2, 3, 5],
  "allowed_ages": [0, 1],
  "nn_checkpoint_path": "checkpoints/best-model.ckpt",
  "llm_ollama_model": "phi4-mini",
  "roast_model_path": "QA_RoBERTA_SQUADv2",
  "target_abstracts": {
    "dragon": "a large, serpentine legendary creature",
    "magic spell": "an arcane incantation or formula"
  }
}
```

**Example `curl` command:**

```bash
curl -X POST "http://127.0.0.1:8000/process" \
     -F "file=@/path/to/your/document.txt" \
     -F "config_json={\"classifier_driver\":\"nn\",\"extractor_driver\":\"llm\",\"llm_ollama_model\":\"phi4-mini\",\"target_abstracts\":{\"dragon\":\"a mythical beast\"}}"
```

**Success Response (Code `202 Accepted`):**

```json
{
  "job_id": "a1b2c3d4-e5f6-7890-1234-567890abcdef",
  "status": "queued",
  "message": "Your request has been queued for processing."
}
```

### 2\. Check Job Status

Poll this endpoint to check the status of your job.

  * **Endpoint:** `GET /results/{job_id}`
  * **Success Response (Code `200 OK`):**
    ```json
    {
      "job_id": "a1b2c3d4-e5f6-7890-1234-567890abcdef",
      "status": "completed",
      "result_path": "output_results/a1b2c3d4-e5f6-7890-1234-567890abcdef.json"
    }
    ```
      * `status` can be: `queued`, `processing`, `completed`, or `failed`.

### 3\. Download Job Result

Once the job status is `completed`, use this endpoint to download the final JSON output.

  * **Endpoint:** `GET /results/{job_id}/download`
  * **Success Response (Code `200 OK`):**
      * The API returns the complete `application/json` file containing the full analysis.

## Training Your Own Classifier

You can train your own `RoBERTaMultiTaskClassifier` using the provided scripts:

1.  **Generate Data (Optional):**
    Use the `data/generator.py` script to create a synthetic dataset using an LLM.

    ```bash
    python data/generator.py
    ```

2.  **Preprocess Data:**
    Clean and prepare the generated CSV file.

    ```bash
    python data_processor.py
    ```

3.  **Train the Model:**
    Run the training script, pointing it to your dataset.

    ```bash
    python train.py --dataset_path "data/cleaned_data_merged.csv"
    ```

    The best model will be saved in the `/checkpoints` directory.
